# worktree 運用規約

エージェントを並行で走らせるときの worktree の扱いと、ローカル確認の手順。

> **`skills/peek/SKILL.md` とセットで使う。**
>
> この規約が定めるのは「どう運用するか」だけ。実際の確認操作は `peek` スキルが行う。
> **規約だけ入れてスキルを入れないと、確認のたびに手で detach することになる。**

## 役割を固定する

| | 役割 |
|---|---|
| **親リポジトリ** | `.env`・`node_modules`・DB が揃った**唯一の実行環境**。確認もここ |
| **worktree** | 編集専用。サーバーは立てない |

worktree には **Git 管理下のファイルしか展開されない**。`.env` も `node_modules` も来ないため、
worktree 側で環境を整えようとすると `.env` の Git 管理化・direnv・DB 分離まで一式が必要になる。
確認を親に寄せれば、その投資がゼロで済む。

## ルール

- **確認は親 worktree で行う。** 作業は必ず別の worktree 側で行う
- 親リポジトリは**作業に使わない**。未コミットの変更を残さない
- **どのブランチにいるかは問わない。** `peek` は detach するので、main である必要はない
  （`peek` 実行後の detached は正常な状態。勝手に別のブランチへ戻さない）
- ただし **worktree で使う予定のブランチは掴まない**。掴むとその worktree を作れない
- 作業用 worktree では**サーバーを起動しない**（環境が未整備なため）
- 動作確認は親で `git switch --detach <対象ブランチ>` してから行う
- **親では編集・コミットしない。** detached でのコミットはどのブランチにも乗らず迷子になる
- 親をエディタで開かない。確認はブラウザで完結する

最後の2行がないと、エージェントは worktree で起動しようとして `.env` を探し始め、
勝手にポートを変え、依存を再インストールする。「ここでは起動しないのが正常」と伝えておく。

## 確認環境の同期

コミットした後、以下を**すべて**満たすときだけ確認環境を同期し、同期したコミットを報告する。

1. 親が detached である（`git -C <親> symbolic-ref -q HEAD` が失敗する）
2. `.git/peek-branch` の内容が、いま作業しているブランチ名と一致する

```
git -C <親> switch --detach $(git rev-parse --abbrev-ref HEAD)
```

一致しない場合は他のブランチを確認中なので**何もしない**。
その旨を一言報告すること（例: 「確認環境は feat-timezone を表示中のため同期していません」）。

**条件2は必須。** これがないと他の人が確認中の画面を奪うため、省略しないこと。

## 置き場所と掃除

- 置き場所は `../<リポジトリ名>-worktrees/<ブランチ名>/` に集約する。
  リポジトリ内に置くと、エディタの検索・リンター・テストランナーが重複ファイルを拾う
- ディレクトリ名はブランチ名と一致させる
- パスに空白が含まれることがあるので、`$2` ではなく `substr($0,10)`、`read` ではなく `read -r` を使う
- 棚卸しはスケジュールタスクで定期実行する。
  **最終コミット時刻を併記しないと放置期間が分からない**

```bash
git worktree list --porcelain | awk '/^worktree /{print substr($0,10)}' | while read -r d; do
  printf "%-12s %s\n" "$(git -C "$d" log -1 --format='%cr' 2>/dev/null)" "$d"
done
```

- マージ済み（`git branch --merged main`）は削除候補
- **削除は `git worktree remove` と `git branch -d` だけ使う。**
  `--force` と `-D` は使わない。危険な削除は Git 自身が止める
  （未コミットの変更があれば remove は失敗し、未マージなら `-d` は失敗する）
- このため**承認を挟まず自動削除してよい**。スケジュールタスクで定期実行できる
- worktree を消してもブランチは残る。`git branch -d` まで一緒にやる

## 並行で走らせないなら

worktree を使わない選択も正解のうち。`settings.json` で切れる（CLAUDE.md ではない）。

```json
{ "worktree": { "bgIsolation": "none" } }
```

代償は並行作業ができないことと、エージェントの失敗が自分の作業に混ざること。
